# 有事实引用的简报

默认运行会生成可直接阅读的模板简报。若使用语言模型，先导出本地事实包，请模型按经营重要性挑选事实、待核实问题与下次动作，再由程序从数据库生成数字与引文。仓库中的示例由模板生成，人工复核状态记录在 review.json。

## 给模型的任务

读取 facts.json 中的 as_of、facts、sources 和 assumptions。选取最多七条与本次交付、营业利润和主要差异有关的事实，按希望读者看到的顺序返回 fact_id。问题从 expense（费用明细）或 mix（结构和确认时点）中选择，动作从 delivery（下月交付）或 finance（下季财务）中选择。输出只包含以下三个字段，用输入中真实存在的 ID 替换示例。

```json
{"fact_ids":["F-示例编号"],"question_id":"expense","action_id":"finance"}
```

在项目根目录核对模型原稿：

```bash
python3 -m nio.report reports/example/facts.json my-draft.json --out build/brief-review
```

该命令保存原稿、规则结果和渲染后的 Markdown。编号无效、额外字段、问题或动作越界时，输出回退到模板并记录原因。数值、正负、期间、单位和实际或预测标签由程序填入。事实包保留原始记录 ID、公式、运行编号、披露文件及其哈希。

## 人工核对

发布前对照原始表格检查金额和比较方向，核对问题与本期情况是否相关。需要补充管理层解释时，可按利润复盘样例在人工终稿中列出原文段落、期间和来源。单独保存修改稿，并在归档副本中登记审核日期、修改和审核状态。程序不会代替审核人把草稿标为已审核。
